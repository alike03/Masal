# Masal

Android TV app: a home interface with IPTV live TV, Plex playback and app shortcuts, in Plex's look. Developed on an NVIDIA Shield. Package `com.alike.masal`, minSdk 26. Runs as a normal app and can also be the device's home screen (`docs/specs/home.md`).

**This file and `docs/specs/` are the source of truth.** Behaviour per feature is in `docs/specs/` (index in `docs/specs/README.md`). When a change alters behaviour, update the matching spec in the same commit; for larger features write or update the spec first and get it confirmed before building.

## Conventions
- Remote: designed for HDMI-CEC TV remotes: D-pad, OK, Back and play/pause only. No number keys, channel keys or Menu, and long press may not arrive. Every key is logged under tag `MasalKeys` (`adb logcat -s MasalKeys`) to check what arrives.
- Local settings (device address, toolchain paths, optional Home Assistant fallback, test values) live in `.env` (gitignored, template `.env.dist`). Never commit machine-specific values, IPs or paths.
- Credentials (Plex, IPTV) are entered on the device through the setup page and stay in the app's private storage. Never hardcode, log or print them.
- `snapshot/` holds personal library data for the real-data tests: gitignored, never commit it.
- Texts: every user-visible text is a string resource in `res/values*/strings_<area>.xml` (English default, `values-de` Swiss spelling with "ss", `values-tr`), keys prefixed by area. Composables use `stringResource`, activities `getString`, other code `Language.text()`. Keep the English texts stable: the JVM tests assert on them.
- `scripts/install.sh` installs, compiles and opens Masal, also on a sleeping TV (without waking it): installing ends the running app, and without this the TV wakes up with the previous app in front. It never starts other apps (`NO_START=1` installs only).

## Stack
Kotlin, Compose for TV (`androidx.tv:tv-material`), Media3 ExoPlayer, OkHttp, Coil, NanoHTTPD (setup page), ZXing.

## Build and install
- JDK 17 and the Android SDK (set `JAVA_HOME` / `ANDROID_HOME`, or put them in `.env`; `local.properties` holds `sdk.dir`).
- `./gradlew assembleDebug` builds; `scripts/install.sh` builds the signed release build when the release key is set up in `.env` (the same as on GitHub, so both install over each other; `BUILD=debug` forces debug, which needs an uninstall first and loses the app's settings), and installs it over network ADB (`TV_ADB` in `.env`), with an optional Home Assistant fallback, then compiles the app on the device (`cmd package compile -m speed`; Android compiles a debuggable APK only to `quicken`, a release build fully): an uncompiled debug APK cold-starts slowly, and as the home screen Masal is cold-started at the moment the device goes to standby. Then it opens Masal, also on a sleeping TV (the screen stays off). Its stale-APK check ignores test sources.

## Releases
Release builds are shrunk with R8 (names kept; rules in `app/proguard-rules.pro`), debug builds and the tests are not: a new library that loads classes by name needs a keep rule there. Check rule changes without a device: `./gradlew assembleRelease` must pass without missing-class errors, and `dexdump` on the APK's `classes*.dex` must still list the kept packages.
`CHANGELOG.md` (Keep a Changelog): every user-visible change adds a line under `## [Unreleased]` in the same commit (Added, Changed, Fixed, Removed; written for users, not commit subjects). Before tagging, rename that section to `## [x.y.z] - <date>`, add a new empty `Unreleased` and the compare links at the bottom; the pipeline publishes the version's section as the release notes and fails a tag without one.
`.github/workflows/release.yml`: on a `v*` tag, tests, builds `assembleRelease` signed with the key from the repository secrets (created once by `scripts/create-release-key.sh`), checks the signature and publishes a GitHub release with `gh release create` (tags with `-` become pre-releases). Manual runs are dry runs that keep the APK as a workflow artifact. Version name comes from the tag (locally `git describe`), version code from the number of commits on every build (`git rev-list --count HEAD`; the pipeline checks out the full history), so the GitHub release of a commit and a local build of it have the same code and a newer commit always installs over an older one (`MASAL_VERSION_NAME` / `MASAL_VERSION_CODE` override both). Actions are pinned to commit SHAs with the version in a comment; when updating, look up the latest release of each action and runner image (`ubuntu-26.04` at the time of writing) instead of guessing.

## Tests (no TV needed)
`./gradlew testDebugUnitTest` runs the Robolectric suites below; video surfaces are off in tests (`VideoPreviews.enabled`), and so is Coil's fade-in (`ImageFades.enabled`, Robolectric's frozen clock leaves images half faded). Values from `.env` are passed to the tests as environment variables.
- `UiFlowTest`: real MainActivity driven with remote keys, fictitious data only, focus assertions. Shots: `app/build/outputs/roborazzi/build/masal-shots/`.
- `RealDataScreensTest`: your own library from `snapshot/snapshot.zip` served by `SnapshotServer` (MockWebServer acting as Plex, Xtream and Bing); skipped without a snapshot. Shots: `.../real-shots/`. Images load asynchronously, so a background photo can be missing in a shot without an app bug. Menu entries are reached with Back + Up/Down (focusing a rail label by text does not work).
- `PlayerOverlayTest`: Plex player controls and subtitle panel. Shots: `.../player-shots/`.
- `LiveOverlayTest`: the live player's info banner (with and without guide) and channel list, fictitious channels. Shots: `.../live-shots/`.
- `GermanScreensTest` / `TurkishScreensTest` (`LocaleScreensTest.kt`): Home and Settings with the device in German and Turkish. Shots: `.../locale-shots/`. UI tests stay offline: `Backdrops.base` and `Graph.plex.accountBase` point at a closed port.
- `RowSliverTest`: a scrolled card row shows no slit of an earlier card at its left edge (`noSliverAtStart`; pixel columns, with an unguarded row as control).
- `AmbientSeamTest`: the colour fill meets the picture frame without a line (pixel columns at the frame edge).
- `SetupPagePreviewTest`: the phone setup page with fictitious settings (PIN sign-in and lockout, no logins on the page, stored Plex token and Seerr key kept for their own address, large bodies refused); saves `build/setup-preview.html`.
- `RedirectSecretsTest`: a redirect to another host gets no Plex token, Seerr key or Seerr user (plain JVM test).
- `XtreamParseTest`: the Xtream channel list read as a stream (numbers, strings and nulls mixed, unknown fields skipped).
- `CategoryOrderTest`: the user's channel category order over the provider's list (plain JVM test).
- `HomeOrderTest`: Home's row order over the rows present (new rows after their default neighbour, rows switched off keep their place; plain JVM test).
- `SeerrTest`: Seerr client against a mock Seerr (key check, search, Discover sliders and their rows with the 12-hour cache, filmography merged per title, title details with seasons, requests as the profile's Seerr user, error text, cache expiry and size), the YouTube stream lookup (YouTube replaced by a stand-in), Plex cast and TMDB id parsing, the paused strip's cast order.
- `PeopleScreensTest`: person page (biography closed with Back), Seerr title page with "Who is asking?" and the season picker, a film request as the person picked, Play for a film in Plex, the paused player's cast row (opened with Down); mock Seerr, fictitious people. Shots: `.../people-shots/`. TV surfaces react to OK, not touch: tests press them through the click semantics action.
- `GuardTest`: restart after a crash (`Guard.kt`, home.md): MainActivity is started again only as the home screen with "display over other apps" granted, at most 3 times in 10 minutes.
- `ProfilesTest`: Plex Home members, signing in as one (PIN refused, server token), requests as the member, revoked token, row choices per profile; plex.tv and the server are a MockWebServer.

Snapshot: made on the device by the debug-only `SnapshotReceiver` (so only with a debug build installed), which drives the app's own `PlexClient` through a recording interceptor; responses are keyed with `debug.key()` (path + sorted query without token), so new Plex calls must also be made in the receiver (Plex search is not recorded yet). Run `adb shell cmd deviceidle tempwhitelist -d 300000 com.alike.masal` (needed while the device sleeps) and `adb shell am broadcast -n com.alike.masal/.debug.SnapshotReceiver`, wait for `snapshot.done` in the app's files folder, pull `snapshot.zip` into `snapshot/`, delete the device copy and scan it for credentials. Logins are replaced by [x] on the device.

Performance rules: the TV tab's and live player's channel lists are grouped once in `MasalViewModel` (`channelCategories`, `recentList`, `favouriteList`) off the main thread; preview players are built only when a preview starts; animated values in `FoldingRows` and the background are read in layout/draw blocks, not in composition; Plex backgrounds are requested at 1280 x 720 (`BackdropWidth`); `Playback` drops its hand-over data when the player closes.

Compose pitfalls found by the tests: a lazy grid that overlaps the element you press Down on is skipped by focus search (keep grids below headers with padding, not contentPadding); scrolling a lazy grid inside an onFocusChanged callback drops focus (scroll from a LaunchedEffect); `focusRestorer` on rows that leave composition crashes ("Release should only be called once"); `graphicsLayer` has no `blendMode` in Compose 1.7 (use `canvas.saveLayer` with a blend-mode Paint); anything drawn to line up with a laid-out element must use the layout's whole pixels (`roundToInt()` like `fillMaxWidth`/`aspectRatio`), a half-pixel offset shows as a thin line on the TV; `setIntent()` in `onNewIntent` makes `ActivityScenario` lose its activity and hang on teardown; infinite animations (Ken Burns) need `mainClock.autoAdvance = false`. An `AnimatedContent` whose content can be empty animates its size from a corner: give every state a full-size box and `using null`. A lazy list keeps its first visible key in view when items change, so new rows above it stay hidden: scroll to the top when the content is replaced (search results). `Map.withDefault { FocusRequester() }` hands out a new requester on every `getValue`, so focus requests miss: store them with `getOrPut`.

## Structure
- `data/` Settings (SharedPreferences; favourites, recent channels, Home apps order, Home live TV row), IPTV (M3U, Xtream API, XMLTV EPG), Plex client (JSON API, hubs, search, collections, genres, clearLogo, UltraBlurColors, streams, subtitle search/download, PIN link, timeline/scrobble), installed apps, Home rows (`HomeRows.kt`: Plex rows and collections chosen for Home, stored as differences from Plex's own Home; a profile's rows are prefixed `p:<id>:`), profiles (`docs/specs/profiles.md`: Plex Home members with their own server token; `Graph.plexFor(item)` gives the client an item was loaded with, so detail pages and the player act as that member), Bing photo-of-the-day backdrops (no key), `foldText()` (accent and Turkish I folding).
- Cast, people and Seerr (`docs/specs/people.md`, `seerr.md`): `data/Seerr.kt` (Seerr client with `X-Api-Key`, requests with `X-API-User` per profile, `SeerrCache` for a week in the cache folder), `data/TrailerService.kt` (YouTube trailers as HLS streams, found with NewPipe Extractor; GPL-3.0, hence Masal's licence), `ui/Trailer.kt` (trailer window and player), `ui/People.kt` (cast row, person page, Seerr title page, season picker, leave-player dialog). Plex's cast comes with `PlexItem.people`; with Seerr the cast is Seerr's (TMDB person ids) via `castFor`.
- `setup/` setup page for phone or computer (`SetupServer`, always running via `SetupHost`, PIN sign-in in `SetupAuth`) and the Settings screen on the TV (spec: `setup.md`).
- `ui/` Home (`HomeScreen.kt`), accordion rows and info blocks (`Rows.kt`, `FoldingRows`), background and previews (`Ambient.kt`), libraries (`BrowseScreens.kt`), search (`SearchScreen.kt`), Apps page, TV tab, side menu, theme and soft scrolling (`Components.kt`).
- `player/` `PlayerActivity` (Plex and live), `PlexOverlay.kt`, `LiveOverlay.kt`, `PlayerSettings.kt` (subtitle look and skip lengths, stored in Settings), `Media.kt` (ExoPlayer with audio focus, buffer capped at 100 MB on the Java heap, Home previews at 32 MB / 30 s, shorter start buffer for live). Live switches channels with two players (current and pending, two TextureView PlayerViews stacked in the FrameLayout, see `live-tv.md`): the pending one plays muted and without audio focus (two players with focus pause each other) and takes over on its first frame; it falls back to one player when the second stream fails. Switching decisions are logged under tag `MasalLive`, never with stream addresses (they contain the IPTV login).
- `Guard.kt`: restart after a crash. `GuardService` runs in its own process (`:guard`, where `MasalApp` skips all setup) and watches a binder of the app process while an activity is started (`GuardLink`); logs under tag `MasalGuard`.
- `debug/` `SnapshotReceiver` (debug builds only).
- Look, assets, fonts and motion timings: `docs/specs/look.md`.
